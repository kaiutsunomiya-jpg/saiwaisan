# さいわいさん — PWA v2（GitHub Pages公開用）

元のSwiftUI版から移植した **さいわいさん** PWA を、曲リスト・練習タイテ・セトリ作成の3画面に拡張したものです。iPhoneとPCに対応します。GitHub Pagesでホスティングできます。

## 今回の更新

### 曲リスト

- 下のナビゲーションバーから「曲リスト」を選択。
- 持ち曲 **22曲**（既存20曲＋下記2曲）を表形式で表示。MC・tuningなどの補助項目は含みません。
- 既定は **Capoが小さい順**。上部の「名前順 ↑」で曲名昇順に切り替え。並び替え設定は端末に保存します。
- 曲をタップすると編集でき、右上の＋で持ち曲を追加できます。
- 新曲：

| 曲名 | Capo | BPM | 演奏時間 |
|---|---:|---:|---:|
| 0時　郵政局 | 7 | 192 | 4:40 |
| さいわい免許センター改 | 4 | 88 | 4:21 |

### 練習タイテ

- 下の「練習タイテ」から表示。左／上が作成中のタイテ、右／下が追加メニューです。
- **練習時間**は任意の分数を設定。初期値は120分。合計時間と残り時間を表示します。
- 6つのメニューを何度でも追加できます。

| メニュー | 初期時間 |
|---|---:|
| 準備 | 20分 |
| 通し | 30分 |
| セクション | 25分 |
| バッファ | 10分 |
| 休憩 | 10分 |
| 片付け | 10分 |

- 追加後の各項目は **5〜240分、5分単位**でプルダウン変更可能。
- 各項目に **備考**欄。曲名・セクション内容などを自由に書けます（最大2,000文字）。入力するたびに端末保存します。
- ⠿ ハンドルをドラッグして並び替え、×で削除できます。
- 右上から **名前を付けて保存・上書き・別名保存・読み込み・削除・コピー**ができます。

### セトリ作成

- 既存PWAのセトリ作成画面を継続。右側から曲／MCなどを追加、並び替え、持ち時間計算、保存・復元、コピーができます。
- 新しい2曲が右側の持ち曲候補にも追加されます。
- 曲リスト側で名前順に切り替えても、セトリ作成の候補は引き続き **Capo順**です。

### PC・スマートフォン対応

- PCでは余白・フォント・行間を広くとり、最大幅1280pxの表示。左右の2カラムを利用。
- スマートフォンでは曲リストをコンパクトな表として表示。
- 練習タイテは備考欄を編集しやすいよう、スマホの縦画面では **上：作成中／下：メニュー**に自動切り替え。
- 下部の3タブで切り替え可能。画像とアイコンは旧版のものを継続利用。

## 既存GitHub Pagesの更新（重要）

**既に `saiwaisan-pwa` を公開している場合、新規リポジトリは不要です。**

1. このZIPを解凍し、`SaiwaiSan_PWA_v2` フォルダの中のファイル・`assets` フォルダを確認します。
2. GitHub の既存リポジトリ `saiwaisan-pwa` を開いて、`Code` → `Add file` → `Upload files` を選択します。
3. 解凍フォルダの **中身**をアップロードします（ZIPや外側フォルダをそのままアップロードしない）。同名ファイルは更新します。
4. `Commit changes` をクリックします。
5. `Settings → Pages` が `Deploy from a branch` / `main` / `/(root)` になっていることを確認します。
6. `Actions` にある Pages のデプロイが成功したら、SafariでURLを開きます。

以前と同じリポジトリ名の場合：

`https://kaiutsunomiya-jpg.github.io/saiwaisan-pwa/`

オンラインで一度開くと、新版のService Workerがオフラインキャッシュを更新します。古い画面が残る場合、SafariでURLを再読み込みしてください。**既存のホーム画面アイコンを消して入れ直す前に、必要なデータをJSONでバックアップしてください。**

GitHub Pagesの設定をまだ行っていない場合は、`Settings → Pages → Deploy from a branch / main / (root)` を選択します。

## データの保存とバックアップ

- 作成中のセトリ、保存済みセトリ、持ち曲、練習タイテ、名前順設定は **その端末のブラウザ領域** に保存します。
- 従来版と同じLocalStorageキーを使用するため、**同じURL・同じブラウザ保存領域で開く限り**、原則として以前のセトリ／持ち曲を引き継ぎ、新しい2曲を自動補完します。
- 旧版のJSONバックアップも読み込みできます。新版のバックアップには練習タイテが含まれます。
- バックアップは「セトリ作成」または「練習タイテ」のフォルダ（保存済み）画面で取得・復元できます。
- iPhoneのSafariとホーム画面に追加したアプリで保存領域が分かれる場合があります。端末移行やアプリ再インストール前に必ずバックアップしてください。

## 3人のメンバー間でのほぼリアルタイム共有について

**実現可能ですが、このv2 ZIPではまだ未実装です。** GitHub Pagesは静的ファイルのホスティングです。現在の持ち曲・セトリ・練習タイテはそれぞれの端末に保存され、他の人へ自動反映されません。

実現する場合、GitHub Pagesのフロントエンドはそのままに、バックエンドとして **Firebase Authentication + Firebase Realtime Database** などを使用するのが一案です。

- バンドメンバー各自がメールアドレスとパスワードなどでログイン。
- 3人のユーザーIDだけが読み書きできるよう、データベースのセキュリティルールを設定。
- 曲、セトリ、練習タイテを共有DBへ保存。
- 変更イベントを監視し、他の端末の画面を接続中に自動更新。
- 同じアイテムを同時編集したときに誰の変更を優先するか、競合対策（バージョンやトランザクション）も追加。

FirebaseのSpark無料枠は2026年11月時点でRealtime Databaseの同時接続上限が100です。3人で利用する規模なら接続数上限は通常問題になりにくいものの、**通信量など他の無料枠上限にも注意**が必要です。初期設定・プロジェクト作成・認証ルール・Firebase接続コードが必要です。

**注意：** 公開リポジトリのソースコードは誰でも閲覧できます。メンバー限定情報を `seed.js` やGitHub Pagesの公開ファイルに入れず、Firebase側の認証・DBルールでアクセスを制御してください。Firebase設定の公開値と秘密情報を混同しないでください。

公式参考資料：
- https://firebase.google.com/docs/auth/web/password-auth?hl=ja
- https://firebase.google.com/docs/database/web/read-and-write?hl=ja
- https://firebase.google.com/docs/database/security/
- https://firebase.google.com/pricing
